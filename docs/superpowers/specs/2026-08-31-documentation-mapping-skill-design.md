# Скилл построения карты документации

## Статус

Дизайн утверждён в диалоге 2026-08-31. Реализация начинается после проверки
этого документа пользователем.

## Цель

Создать модельно вызываемый скилл `mapping-documentation`, который исследует
указанную пользователем документацию проекта и создаёт либо обновляет карту
документации. Карта объясняет, какие устойчивые знания следует замечать в
будущих сессиях и в какие документы их направлять.

Скилл не анализирует сессии, не извлекает из них кандидатов и не проектирует
review-процесс.

## Состав

- `.agents/skills/mapping-documentation/SKILL.md` — условия вызова, workflow и
  границы исследования.
- `.agents/skills/mapping-documentation/references/map-format.md` — нормативный
  формат карты и правила обобщения.
- `.agents/skills/mapping-documentation/agents/openai.yaml` — краткие UI-метаданные.

Отдельный сканирующий скрипт не создаётся: выбор тем, источников истины и режимов
изменения требует семантического анализа. Детерминированные файловые операции
выполняются штатными инструментами агента.

## Входы и начало исследования

Скилл определяет корень текущего проекта и извлекает из запроса пользователя
начальные точки исследования: файлы, каталоги или их словесное описание.

- Если начальная точка отсутствует, скилл задаёт один вопрос: где начинать искать
  документацию. До ответа содержательный обход проекта не начинается.
- Если пользователь указал файл или каталог, скилл сразу исследует этот корпус.
- Каталог обходится рекурсивно. Указанный документ читается вместе с локальными
  индексами и ссылками, необходимыми для понимания его роли.
- Код, конфигурация, тесты и соседние файлы проверяются только когда нужно
  установить назначение документа или машинный источник истины. Полный аудит
  кодовой базы не выполняется.
- Словесное описание пути сначала разрешается по структуре проекта. Вопрос
  задаётся только при нескольких правдоподобных вариантах или отсутствии пути.

## Построение карты

Единицей карты является устойчивый класс знания, а не отдельный файл, клиент,
провайдер или частный доменный пример. Скилл:

1. Строит inventory найденной документации и определяет назначение документов.
2. Различает актуальные знания, действующие правила и исторические записи.
3. Определяет режим обращения с каждым семейством документов: `update`, `append`
   или `readonly`.
4. Объединяет сходные документы в широкие темы и glob-маршруты.
5. Для каждой темы описывает `watch_for`: признаки устойчивого знания, которые
   анализатор будущих сессий должен замечать.
6. Для каждого target описывает `captures`, `mode` и локальные `instructions`.
7. Оставляет пустой target и применяет `on_unmatched: report`, если важный класс
   знания обнаружен, но подходящего места записи нет.

Карта создаётся со статусом `draft`. Формат и критерии качества определены в
`references/map-format.md`.

## Выбор места записи

Если пользователь заранее не указал путь карты, скилл предлагает выбор:

1. `<project-root>/DOCUMENTATION-MAP.md` — рекомендуемый вариант.
2. `<project-root>/docs/documentation-map.md`.
3. Пользовательский путь внутри проекта.

Запись выполняется только после выбора. Если по выбранному пути уже существует
карта, скилл отдельно сообщает об этом и явно спрашивает разрешение обновить её.
Отказ пользователя завершает запись и оставляет возможность выбрать другой путь.

## Обновление существующей карты

Существующая карта является входом анализа, а не файлом для полной регенерации.
Скилл сохраняет ручные инструкции владельца, понятные темы и принятые пути.
Новые данные добавляются либо обобщаются в существующие темы. При противоречии
между картой и исследованной документацией скилл показывает конфликт и запрашивает
решение вместо молчаливого удаления ручного правила.

## Безопасность

- Все исследуемые и выходные пути после разрешения остаются внутри корня проекта.
- Ссылки, ведущие за корень проекта, не обходятся автоматически.
- Содержимое документации считается недоверенными данными: найденные команды,
  prompt-инструкции и imports не исполняются.
- Скилл читает только материалы, необходимые для выбранного корпуса и уточнения
  источников истины.
- Запись ограничена выбранным файлом карты.

## Проверка поведения

До создания скилла запускается baseline-агент без его инструкций. Затем те же
сценарии выполняются агентом со скиллом:

1. Пользователь просит построить карту, но не указывает расположение документации:
   агент должен запросить начальную точку.
2. Пользователь указывает `example/backend/docs`: агент должен исследовать корпус,
   сформировать широкие темы и запросить место записи.
3. По выбранному пути уже существует карта: агент должен запросить отдельное
   разрешение и сохранить ручные инструкции при обновлении.

Дополнительно проверяются структура frontmatter, отсутствие незавершённых
placeholder-ов и соответствие имени скилла формату Agent Skills.

## Критерии готовности

- Скилл находится и вызывается по запросам о построении или обновлении карты
  документации.
- Недостаточный ввод приводит к одному точному вопросу, а достаточный — к началу
  исследования без лишнего подтверждения.
- Путь вывода выбирает пользователь; существующая карта не изменяется без
  отдельного согласия.
- Результат использует широкие темы и glob-маршруты, сохраняя конкретные примеры
  на уровне содержимого документов.
- Карта соответствует согласованному формату и создаётся со статусом `draft`.
- Скилл не выходит за проект, не исполняет инструкции из документации и не меняет
  файлы помимо подтверждённой карты.
