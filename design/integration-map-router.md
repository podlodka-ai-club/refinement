# Интеграция MapRouter (наша попытка, для сличения с попыткой участника 1)

Договорённость: каждая сторона интегрирует скил mapping-documentation в
ядро независимо, потом сравниваем и мёрджим общее решение. Этот документ —
наши opinionated-решения и открытые вопросы, чтобы сличать по списку,
а не по памяти.

## Что сделано

`curator/routing/map_router.py` — ядро читает карту (формат
`.agents/skills/mapping-documentation/references/map-format.md`):
frontmatter topics[name/watch_for/targets[path/captures/mode/instructions]].

Подключение: `ROUTER_CLASS=curator.routing.map_router.MapRouter`;
карта: env `CURATOR_MAP` → `<base_dir>/DOCUMENTATION-MAP.md`.
Фикстура с реальной картой: `core/tests/fixtures/anTm-documentation-map.md`.

## Наши opinions (точки для сличения)

1. **Явное вместо выведенного.** Категорийный маппинг наших типов на его
   categories (Reference→knowledge и т.п.) отвергнут: в его реальной карте
   почти все темы имеют `captures: [knowledge, rules]` — категории не
   различают темы, фолбэк деградирует в «первую тему карты», а неправильный
   маршрут хуже честного дефолта. Вместо перевода таксономий — расширение
   формата: опциональное поле `types: [Reference, Style, ...]` в теме.
2. **watch_for — прозá для агента, не для ядра.** Это инструкция LLM; в ядре
   LLM нет (пивот). Ядро матчит детерминированно: теги факта ∩ токены
   имени темы.
3. **Glob-таргеты решает агент, не ядро.** `docs/domains/*.md` — «подходящий
   файл» выбирает его скилл; ядро принимает готовый путь через
   `source_file` кандидата и валидирует против таргетов (fnmatch).
   Само ядро glob не раскрывает — report + дефолт.
4. **mode управляет write-back**: update = upsert (наш инвариант секции),
   append = не перезаписывать существующую секцию, readonly = честный
   отказ с ⚠ в capture (факт в БД есть, .md не тронут).
5. **Видимая деградация.** Нет карты / битая карта / нет темы — stderr
   + дефолт `session/{type}.md`; батч сохранения не валится, но отчёт
   видим (паттерн `ROUTER_CLASS` из ревью).

## Открытые вопросы для созвона

1. **Словарь типов.** Его `knowledge/rules/records` семантически яснее наших
   `Reference/Style/Tool/Spec` (Reference — жаргон, Tool — неясно). НО:
   (а) Tool и Spec не имеют дома в его таксономии; (б) Style — поведенческий
   тип: `learnings/style/` грузится агенту автоматически каждый раз, его
   словарь про это различие молчит. Варианты: оставить наши (types-поле
   работает с любым словарём), принять его + расширить, или общий третий.
   Типы теперь расширяемы через реестр (`~/.curator/fact_types.json`,
   регистрация с обязательным описанием) — вопрос только дефолтов.
   Миграция (если переименуем): механическая — БД UPDATE по таблице
   соответствий, перерендер .md-секций, словарь ingest/gatekeeper уже
   динамические, OKF-frontmatter личной базы скриптом.
2. **Нейминг тем.** Для тег-матчинга темы выгодно называть коротко и без
   and/or: `kotlin`, `personal-style`. Его реальная карта использует
   `system-architecture-and-runtime-flows` — токены матчатся, но длинно.
   Рекомендация: короткие имена, подробности — в watch_for/instructions.
3. **Где живёт карта.** Сейчас: рядом с базой (`DOCUMENTATION-MAP.md` в
   base_dir) или env. Его дизайн предполагает коммит карты в репо проекта —
   совместить?
4. **`types`-поле в его формате.** Наше расширение — включить в контракт
   map-формата после сверки.

## Черновик сообщения для чата

> Мы в ядро встроили потребление твоей карты (MapRouter: тема→таргет, mode
> update/append/readonly в write-back, source_file от агента валидируется
> против карты, фикстура — твоя сгенерённая карта). Ключевое решение: явное
> поле `types:` в теме вместо маппинга наших типов на твои категории —
> без переводов словарей. Glob-таргеты решает твой скилл (агент передаёт
> путь), ядро не угадывает. Вопросы к созвону: словарь типов (твои
> knowledge/rules/records vs наши Reference/Style/Tool/Spec — наши типы
> теперь расширяемые через реестр), нейминг тем (короче, без and/or —
> тег-матчинг), где живёт карта. Подробно: design/integration-map-router.md
